# Completing the 2.3.0 release: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release CanSNPer2 2.3.0 together with the converted CanSNPer2-data (master and dev) and a CanSNPCreator that writes the new format. Before that, close the import paths where a user receives a wrong or empty result without a clear message.

**Architecture:** Three repositories, one release.
- CanSNPer2 gets a `scheme_info` table in the database and stricter import paths. Every bad input on the paths in this plan ends with one clear message and a non-zero exit. A table-driven test suite holds this in place.
- CanSNPer2-data fills `scheme_info` when it builds, and converts the dev-only schemes.
- CanSNPCreator moves from one joined position to (sequence, position) throughout.

**Tech stack:** Python 3.11-3.14, sqlite3, pytest. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-21-per-sequence-positions-design.md`. That spec still holds. This plan adds the user's decisions of 2026-11-21:
- Nothing is merged to master until all of this is done.
- The database gets a scheme-info table in 2.3.0.
- The error-reporting work and CanSNPCreator 0.6.0 ship with 2.3.0, not after it.

**Context:** The state on 2026-11-21:
- CanSNPer2 #68 (per-sequence positions) is merged into `dev_2.3.0` (47d2633).
- CanSNPer2-data #33 (five master schemes converted) is open and green, and is not merged.
- On CanSNPer2-data dev, brucella_suis and brucella_anthropi are still in the old format.
- CanSNPCreator 0.5.1 writes and reads only the old format.

A survey of every import path found these gaps:
- Several paths only log a warning and exit 0: `--mod_file`/`--annotation` on an existing database, the warning-only `query()` wrapper, reference download with an empty list or with the base check skipped, and typing with database genomes that have no reference file.
- A prebuilt `.db` says nothing about its scheme, status or origin.
- A `--scheme` download from a branch in the old format gives a message that does not fit the situation.

## Global constraints

- All 2.3.0 format rules from the earlier plan still apply. SNPs are (`sequence`, `sequence_position`); old input is refused with the `--convert` hint.
- **Rule for every bad input:** a single message that names the file or object and says what to do, a non-zero exit, and no Python traceback. A warning with exit 0 is allowed only where this plan says so.
- **`scheme_info` is optional to read.** A 2.3.0 database without it is accepted, with one warning. It never blocks typing.
- **Language:** modest scientific language in code, docs and messages. No Unicode in Nextflow files.
- **Attribution:** no Claude attribution in commits or PRs; the user is the sole author.
- **Branches:**
  - CanSNPer2: `release_2_3_0_completion` from `upstream/dev_2.3.0`, PRs into `dev_2.3.0`.
  - CanSNPer2-data: update PR #33's branch `per_sequence_positions`, plus a new `per_sequence_positions_dev` from `origin/dev`.
  - CanSNPCreator: `per_sequence_positions` from `origin/main`. Its local, uncommitted changes in `benchmarks/bench.sh` and `benchmarks/cansnper2_type.sh` belong to the user. Leave them untouched; ask before starting Part C.
- **Test commands:**
  - CanSNPer2: `PYTHONPATH=$PWD /Users/andreassjodin/miniforge3/bin/python -m pytest -q`.
  - Data and CanSNPCreator: the scratch venv with CanSNPer2 2.3.0 installed in editable mode (`venv230`).

## Review focus

1. **Exit codes in automation:** a pipeline that runs CanSNPer2 must be able to rely on the exit code. Every path in the Task A2 table is a CLI test asserting exit code and message, with no traceback.
2. **Draft and unknown origin:** a database that does not record its origin, or records draft status, still types. The user sees one warning line at the start of every command that opens it.
3. **Partial modification:** a failed `--mod_file`/`--annotation` on an existing database must leave that database byte-identical.
4. **RefSeq-named references in CanSNPCreator:** they are converted to GenBank names at export, or refused with the assembly-report hint. They are never written under RefSeq names.
5. **Cross-repo round trip:** a CanSNPCreator export must pass CanSNPer2-data `validate.py`, build with CanSNPer2 2.3.0, and type with the same result as before the format change.

## Part A: CanSNPer2 (branch `release_2_3_0_completion`)

### Task A1: scheme_info table

**Files:**
- Modify: `CanSNPer2/modules/InitiateDatabase.py` (schema), `DatabaseConnection.py`, `SNPDatabase.py`, `FetchScheme.py`, `CanSNPerTree.py`, `DownloadGenomes.py`, `ExportDatabase.py`, README.
- Create: `CanSNPer2/modules/SchemeInfo.py`, `tests/test_scheme_info.py`.

**Interfaces:**
- **Table:** `scheme_info(key TEXT PRIMARY KEY, value TEXT)`. `--create` and `--import` always write the keys `format` (`"2.3"`), `built_with` (the CanSNPer2 version) and `built` (an ISO date). Keys set when known:
  - `scheme`
  - `status` (`verified`, `draft`, or `unknown`)
  - `source` (repository or folder)
  - `ref`
  - `commit`
  - `known_issues` (comma-separated snp_ids)
- **API:**
  - `read_scheme_info(path) -> dict`, which returns `{}` when the table is absent.
  - `write_scheme_info(conn, info: dict)`.
  - `describe(info) -> str`, one line, for example: `brucella_suis (draft), FOI-Bioinformatics/CanSNPer2-data dev@abc1234, built 2026-11-21 with CanSNPer2 2.3.0`.
  - `scheme_notice(path) -> (level, text)`. The level is a warning when the table is missing, when status is `draft` or `unknown`, or when `known_issues` is non-empty. Otherwise it is info.
- **CLI:**
  - `CanSNPer2-database --database DB --info` prints all keys and exits 0.
  - `--create` and `--import` accept `--scheme_name`, `--scheme_status` and `--scheme_source`, and write them to the table.
  - `FetchScheme.build_scheme` writes scheme, status (from the scheme README), source, ref, commit (`unknown` when the API was unavailable) and `known_issues` (from `schemes.toml`). It keeps writing `<db>.source.json` as it does today.
- **Where the notice is shown:** typing start-up, `CanSNPer2-download --database`, and `--export` each log `scheme_notice` once, before their work.
  - The text goes to stderr at the given level. This matters because info-level lines are hidden by default.
  - A missing table gives the warning: "the database records no scheme information (built with CanSNPer2 before 2.3.0 or by hand); check where it came from".
  - The `--export` path writes no table rows to the export files.

  - `test_unknown_commit_is_recorded_as_unknown`

### Task A2: no silent or warning-only failures on import paths

**Files:**
- Modify: `ModifyDatabase.py`, `DatabaseConnection.py` (the `TaxonomyDBConnection.query` callers), `ReadTaxonomy.py`, `ReadTaxonomyCanSNPer.py`, `SourceCheck.py`, `DownloadGenomes.py`, `FetchScheme.py`, `CanSNPer2.py`, `CanSNPerTree.py`, `SNPDatabase.py`.
- Create: `tests/test_import_errors.py`.

**Behaviour.** For each input, what the user gets after the change. Every row ends in a non-zero exit unless the row says otherwise.

| Path | Input | After |
|---|---|---|
| `--mod_file` / `--annotation` / `--references` on an existing database | SNP on an unknown node; SNP on an unknown genome; short row; old header; failed insert | Runs `check_sources` against the existing tree and references first. Works on a copy and replaces the database only on success, so a failed run leaves it byte-identical. Exit 1 with the problem list. |
| `--create` / `--import` | Tree, node or link insert fails | `DatabaseWriteError`, the started file is removed, exit 1. Today only SNP and reference inserts are covered. |
| SourceCheck | References row with empty `genbank_id`, or an id not matching `GC[AF]_\d{9}\.\d+` | Refused with file:line. |
| `--remove` | Unknown `--parent`, or the root | Exit 1 with a message (behaviour exists; tests are added). |
| `CanSNPer2-download --scheme` | Branch in the old format | Message: "scheme X on <repo>@<ref> uses positions on the joined reference (before 2.3.0); use CanSNPer2 2.2 for it, or a branch converted for 2.3.0". Exit 1. |
| `CanSNPer2-download --scheme` | sqlite or OSError while building or replacing | Message, exit 1, no `.part` left behind. |
| `CanSNPer2-download --scheme` | Missing manifest or hash, GitHub source | Error, unless `--allow_unverified` is given. A `--data_dir` source keeps the warning. |
| `CanSNPer2-download --database` | Database lists no reference genomes | Exit 1 ("nothing to download"). |
| `CanSNPer2-download --database` | NULL or empty accession | Reported per genome as failed, with the refid, and no child-process traceback. |
| `CanSNPer2-download --database` | The SNPs cannot be read, so the base check would be skipped | Exit 1. |
| Typing start-up | Database genomes without a `<genome>.fna` in `--refdir` | Exit 1, naming the genomes and the `CanSNPer2-download --database` command. Today these SNPs are silently never compared. |
| Typing start-up | The SNPs cannot be read, so the reference check would be skipped | Exit 1. |
| Typing start-up | Database with no SNPs or no references | Exit 1 up front, not per sample. |
| Typing start-up | snp_annotation rows on node ids missing from `nodes` or `tree` | Exit 1, listing them. Nodes without SNPs remain allowed. |
| Every command | Any unexpected exception at the top level | One line "CanSNPer2 stopped: <type>: <message>; run with --debug for details", exit 2. The traceback is shown only with `--debug`. |

Warnings with exit 0 stay as they are for:
- a draft or unknown scheme (A1);
- fewer than 20% base mismatches;
- extra reference files in the folder;
- `--no_references`.

**Tests:** `tests/test_import_errors.py` is table-driven. Each case gives a fixture builder, the CLI arguments, the expected exit code and a message fragment. Each case asserts all three of those, plus no `Traceback` in stderr and, where the table says so, no changed or partial file. One case per table row; the existing tests stay where they are.

## Part C: CanSNPCreator 0.6.0 (branch `per_sequence_positions`)

Before starting, ask the user about the uncommitted benchmark changes: should they be committed first or left aside?

### Task C1: scheme model and reader

- `scheme.SchemeSnp` carries `sequence: str` and `position: int`, where the position is on that sequence. There is no global position.
- `scheme.read_scheme` reads the new headers by column name. An old header raises an error naming `CanSNPer2-database --convert`. `SNP_COLUMNS` and `SNP_SET_COLUMNS` move to the new headers, and `report.py:119-125` follows.
- **Tests:** convert the fixtures in `tests/conftest.py` (`SNPS`, `REFERENCES`, `written`, `edit`). Add `test_old_header_names_the_conversion_command`.

### Task C2: export

- `write_scheme` and `write_snp_set` write `score.contig` as `sequence` and `score.position` as `sequence_position`. The `contig.start` join goes away.
- **Sequence names must be GenBank accessions.**
  - `export` gets `--contig-aliases`, the existing `read_contig_aliases`, which reads an NCBI assembly report or a UCSC chromAlias table. A contig named by RefSeq (`NC_`, `NZ_`) is written as its GenBank alias.
  - Without an alias, export stops. The message names the contig and asks for `--contig-aliases <assembly_report.txt>`.
  - A name that matches neither pattern (a local assembly) is written as it is, with a warning that CanSNPer2-download will not find it.
- **Tests:** update `tests/test_export.py`. Rewrite `test_positions_are_counted_over_the_concatenated_genome` as `test_positions_are_given_per_sequence`, with B.2 at `chr2 201`. Add:
  - `test_refseq_contigs_are_written_with_genbank_names`
  - `test_refseq_contigs_without_aliases_are_refused`
  - `test_the_export_builds_with_cansnper2_230`. This runs `python -m CanSNPer2.SNPDatabase --create` from the venv and is skipped when CanSNPer2 2.3.0 is not importable.

### Task C3: audit, alignment audit and typing report

- `cansnp_audit.py`:
  - Reference bases are read at `reference.contig(snp.sequence)` and position, not through `locate` on a global position.
  - Clusters and shared-position checks are keyed by `(genome, sequence, position)`.
  - Score matching (`:390-445`) compares (contig, position) directly.
- `alignment_audit.py`: where an alignment column is needed, use `contig.start + position - 1` as an internal value only. It is never written out.
- `typing_report.py`:
  - Output columns gain `sequence`.
  - `read_observed` reads CanSNPer2 2.3.0 result files (`Name Reference Sequence Pos ...`) keyed by `(node, sequence, position)`.
  - A 2.2 result file is refused with a message to type again with 2.3.0.
  - The texts naming "CanSNPer2 2.2.1 and 2.2.2" change to 2.3.0 where they describe current behaviour.
- **Tests:** convert the fixtures in:
  - `test_audit.py`. The position edits use the new column.
  - `test_alignment_audit.py`, `test_audit_round3.py`, `test_audit_round4*.py`, `test_reports.py`.
  - The published-scheme tests read `../CanSNPer2-data/schemes/` and no longer `source/`, which is stale. They skip when that folder is absent or still in the old format.
